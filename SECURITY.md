# Security Policy

## Reporting a vulnerability

Please report vulnerabilities privately through GitHub's
[private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability):
open the repository's **Security** tab and choose **Report a vulnerability**.

Do not open a public issue, pull request or discussion for a suspected
vulnerability.

Include what you can of:

- the affected version or commit;
- the component (server, CLI, Helm chart, CI action);
- steps to reproduce or a proof of concept;
- the impact you expect.

## Supported versions

Only the latest release receives security fixes. Upgrade to it before
reporting, if you can, to check the issue still exists.

## What to expect

- Acknowledgement within 5 business days.
- An initial assessment (accepted, needs more information, or declined, with
  the reason) within 14 days.
- Fixes for accepted reports ship in a new release. The advisory is published
  once the release is out, crediting the reporter unless they prefer otherwise.

Please give us a reasonable time to ship a fix before disclosing publicly.
